## 2. Exact observed occurrence

The SPServices sequence treated “finding a useful set of medical-document
properties” as the problem to solve. The project had already built a property
catalog, profiles, scanner-related assets and extensive governance evidence, so the
framing inherited those artifacts as the presumed intervention space.

The roadmap contained an outcome-facing objective and a list of candidate method
families, but no distinct, versioned problem statement. Its method list contained
standards-first, expert-first, AI-assisted, corpus-observation, hybrid and defer
options. Most were capabilities or method components, not complete alternative
solutions to an independently evidenced user problem.

O1 improved the language by asking which decisions properties should support and by
allowing no-new-property results. It nevertheless preserved properties as the object
whose usefulness would be evaluated before establishing whether users had a material
classification, findability, workflow or governance problem and whether properties
were a credible remedy.

The later T1 design then accumulated six scenarios, six method configurations,
twelve synthetic examples, five reviewer roles, two complete review cycles and
twelve governed outputs without first validating the solution-neutral problem.

On 2026-09-07 the project steward challenged the sequence: embedding problem
definition in the project objective resembles creating a solution and then looking
for a market problem to which it can be applied. That challenge exposed a SymK
control gap rather than only a local drafting defect.

## 5. Question, claim and requested change

**Question:** Can current SymK project governance prevent a technically mature or
preferred solution from defining the problem that supposedly justifies it?

**Scoped claim:** Not reliably. Current profiles can expose deliverable-shaped
objectives and inadequate method comparison, but they do not require an independently
reviewable problem claim before Objective Acceptance.

**Requested change:** Add a problem-first project-governance profile that introduces
bounded Problem Discovery, Problem Acceptance, a solution-contamination test,
solution-neutral objective traceability, complete alternative configurations and an
admissible no-material-problem disposition.

## 8. Grounds, counterevidence and defeaters

### 8.1 Supporting grounds

- O1 explicitly recorded no validated production search or user-interface
  requirement, no named operational users or decision frequency, and no quantified
  user benefit or error tolerance.
- Stage 6 showed gaps in provisional profiles but did not establish that users had a
  material problem or that properties would solve it.
- Package A's black-box objective test protects outcomes from deliverable
  substitution but assumes an adequate problem basis already exists.
- Problem-Investment v0.1 says to state a problem situation but does not require
  separate acceptance, disconfirmation criteria or independence from a preferred
  intervention.
- The simplified T1-v0.3 draft still selected a property/profile question, showing
  that local simplification alone did not remove the inherited assumption.

### 8.2 Counterevidence and mitigating controls

- Roadmap v0.3 asked which decisions require properties and included a defer/no-new-
  properties candidate.
- O1 preserved uncertainty and allowed retaining existing properties or rejecting
  the scanner.
- Package A requires an externally meaningful objective and credible alternatives.
- Problem-Investment v0.1 requires inaction, a simpler alternative and a versioned
  problem situation.

These controls reduce but do not prevent solution contamination. They allowed
properties to remain the assumed intervention class while asking how best to
evaluate or discover them.

### 8.3 Potential defeaters

The upstream claim would be weakened if evidence showed that another accepted SymK
control already requires a separately accepted, solution-independent problem claim
before O1, or that the SPServices property work was based on attributable prior user
evidence not represented in the reviewed project record.

## 9. Alternatives and counterfactuals

1. **Local SPServices correction only:** faster, but leaves SymK able to repeat the
   error elsewhere and risks designing the general method around a preferred local
   answer.
2. **Interpret existing wording more strictly:** avoids a new profile, but remains
   dependent on reviewer inference and offers no explicit no-problem gate.
3. **Add a checklist only:** may flag missing fields, but cannot supply the missing
   decision type or traceability semantics.
4. **Problem-first SymK correction:** creates a reusable upstream control while
   leaving each Domain responsible for substantive problem evidence.
5. **No change:** accepts recurrence risk and treats the SPServices occurrence as an
   isolated drafting failure.

The proposed disposition is alternative 4, with proportional records so the new
control does not create another governance-heavy program.

## 11. Benefits, harms and burden distribution

The correction may reduce wasted engineering, expert and governance effort and make
no-problem conclusions legitimate. It may also delay urgent work or burden small
projects if applied mechanically. Intended users and affected subjects benefit when
their observed conditions, not available tools, define the investment question.
Project teams bear the cost of early problem evidence and possible abandonment of
favored solutions.

## 15. Transfer conditions and generalization boundary

The generalizable proposition is limited to material project investment:

> Before an objective, solution comparison or execution release governs material
> work, the project must expose an independently reviewable problem, opportunity,
> obligation or knowledge-gap claim and test whether a preferred intervention has
> defined that claim.

The proposition does not require every minor task, defect fix, mandate or emergency
containment action to conduct market research. It does not require a commercial
customer. Research uncertainty, internal capability gaps and legitimate obligations
may be valid problem situations when evidenced and bounded.
