# PLC_META — 1.4 Discovery Methodologies (PLC_1 Toolbox)

## Purpose

List the **methods and tools** that can be used across PLC_1 (Discovery) to build a deep understanding of any product idea.

## Method families

1. **Customer & stakeholder exploration**
   - Problem interviews.
   - “Day in the life” walkthroughs.
   - Jobs To Be Done mapping.
   - Journey mapping (before/after product).

2. **Market & ecosystem scanning**
   - Competitor teardown (features, pricing, messaging).
   - Adjacent markets / analogues (“who solved a similar problem elsewhere?”).
   - Analyst reports, public case studies, community discussions.

3. **Internal knowledge mining**
   - Past projects and proposals.
   - Existing scripts/tools already used informally.
   - Known failure modes and near-misses.

4. **Technical & operational constraints**
   - Platform capabilities and limits.
   - Security, compliance, data residency constraints.
   - Integration surface (APIs, events, logs, agents).

5. **Risk-focused framing**
   - “How can this go wrong?” sessions.
   - Pre-mortems (assume the project failed, list reasons).
   - Scenario analysis for edge cases.

## Usage

Each product-specific PLC_1 should:

- Explicitly state **which methods were used**.
- Capture **evidence and learnings** in the 1.1–1.5 documents.
- Use 1.6 to **decide** whether the idea deserves to move into architecture and engineering.

This file is **generic**; product-specific adaptations belong in each product’s `1.4` file.
