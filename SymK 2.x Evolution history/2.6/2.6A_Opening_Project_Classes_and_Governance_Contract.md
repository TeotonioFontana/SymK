# SymK 2.6 — Opening, Project Classes and Governance Contract

**Status:** Scaffold only — work package not authorized or started
**Stage status:** 2.6 closed
**Normative effect:** None

## Purpose

Freeze project evidence and define project classes, charter forms, authorities and conformance claims.

## Entry conditions

- Formal 2.6 opening is effective.
- Required predecessor packages have passed.
- Inputs and authority are exact, current and frozen.
- No unresolved issue invalidates the inherited baseline.

## Required inputs

2.5 packages; 2.3 governance; project inventories.

## Required analysis

- State questions, alternatives, claims and exclusions explicitly.
- Apply jurisdiction, authority, status, counterexample and compatibility tests.
- Preserve dissent, uncertainty, tensions and deferred remainders.
- Record affected artifacts, projects, identifiers and downstream obligations.
- Separate evidence from decision and semantic disposition from physical migration.
- Require competent procedure for every governed change.

## Deliverables

Opening control, project taxonomy and draft governance contract.

## Non-effects

This scaffold does not open the package, decide an issue, revise or migrate a source, change Authority/status, accept a stage, authorize its successor, or commit project changes.

## Gate

Projects have explicit status, owner, scope, version and inherited baseline.
