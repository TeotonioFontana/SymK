# SymK 3.1 — Project Name and Identity Expression Stage Frame

**Status:** Scaffold only — not effective
**Stage:** Closed

## Purpose

Challenge the project/framework name only after the complete 3.0 identity, Constitution, semantics, governance, evidence, corpus and engineering realization can serve as the evaluation object.

## Governing separation

```text
accepted SymK 3.0 / 3.0E
          |
          v
semantic name challenge and decision
          |
          v
conditional migration authority
          |
          v
post-migration verification and later release
```

A semantic decision does not rename anything automatically. Availability, aesthetics, trademark evidence or migration cost does not decide semantic fitness alone.

## Required tests

Identity fidelity; engineered-object fidelity; participant neutrality; Cooperation non-entailments; bounded jurisdiction; newcomer comprehension; distinctiveness; international usability; legal/domain feasibility; lineage safety; derived-project/package compatibility; migration feasibility; reversibility; and future fitness.

## Version rule

SymK 3.0 remains immutable under its historical proper name. If 3.1 selects a successor name, the decision must state the first later version for which it is effective and whether the material identity-expression change requires a larger release boundary.

## Successful exit

An exact naming state is competently decided; any authorized migration is verified; SymK 3.0 remains discoverable and unrewritten; affected projects and artifacts have explicit compatibility/alias paths; dissent and reopening conditions remain visible.

No scaffold text satisfies this exit.
