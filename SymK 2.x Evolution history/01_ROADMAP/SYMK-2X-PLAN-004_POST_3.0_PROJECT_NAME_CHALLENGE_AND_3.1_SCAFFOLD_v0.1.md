# SYMK-2X-PLAN-004 — Post-3.0 Project-Name Challenge and 3.1 Scaffold

**Status:** Controlled sequencing amendment — Proposed; no name decision or stage opening
**Version:** 0.1
**Date:** 23 August 2026
**Current baseline:** `2.1-rc.1`; 2.1.10 Stream H open
**Authority:** project-steward proposal that the name be challenged only after 3.0 is closed and 3.0E is accepted, followed by instruction to add the proposal to the project
**Evidence:** `SYMK-2X-EV-172`
**Change:** `SYMK-2X-CH-125`
**Relates to:** `SYMK-2X-PLAN-003` and `2.1.11.1A_PROJECT_NAME_AND_IDENTITY_FITNESS_REVIEW.md`

## 1. Adopted project sequencing

The substantive challenge to the project/framework name is deferred until after:

1. the complete SymK 2.x review and upgrade has passed its governed stages;
2. 3.0 has been frozen, verified and accepted;
3. 3.0E has closed the first consolidated release; and
4. a separate competent instruction opens 3.1.

This is a sequencing decision only. It does not decide whether the name is obsolete or what should replace it.

## 2. Provisional naming convention through 3.0

Until 3.1 decides otherwise:

> **“SymK” is the controlled historical proper name of the project and framework. “Symbiotic Knowledge” is preserved as historical lineage and is not presumed to be the current expansion, complete definition, constitutional purpose or engineered object. Use of “SymK” creates no semantic or constitutional commitment beyond the exact accepted identity and jurisdiction records.**

Every artifact through 3.0 must interpret the proper name through accepted decisions, especially DR-017, rather than derive meaning from the historical expansion.

## 3. Why the challenge follows 3.0

The sequence permits the name to be evaluated against the complete object it is supposed to identify:

- Ratified constitutional baseline;
- accepted concepts, principles and package system;
- effective governance;
- legacy dispositions;
- derived-project evidence;
- grounding validation;
- consolidated corpus;
- engineering projections; and
- the exact first consolidated release.

It also makes 3.0 an immutable before-state for any later identity-expression or naming migration.

## 4. Pre-3.0 obligations

Deferral does not erase the question. Before 3.0:

- 2.1.11 records this exact route and verifies that the historical expansion is not presented as current semantics automatically;
- 2.2–2.9 treat “SymK” as a controlled proper name;
- 2.4 preserves and dispositions historical name-bearing artifacts but does not decide the current framework name;
- 2.8 preserves aliases, provenance and migration readiness but does not execute a framework rename;
- 3.0B verifies consistent provisional-name use without assessing permanent fitness; and
- 3.0E explicitly states that release acceptance does not Ratify, permanently endorse or close challenge to the name.

## 5. 3.1 scope

Stage 3.1 owns:

1. the semantic challenge to “SymK” and “Symbiotic Knowledge”;
2. explicit alternatives: retain name/expansion, retain proper name while retiring expansion, adopt a new expansion, adopt a successor name, or return for more evidence;
3. newcomer, jurisdiction, identity, international, distinctiveness, domain/trademark and migration evidence;
4. the competent naming decision;
5. conditional physical migration if a successor is selected; and
6. post-migration authority, lineage, compatibility and release verification.

## 6. Dependency and authority

3.1 requires accepted 3.0E and a separate opening instruction. The naming decision must be made by competent identity/constitutional authority under effective 3.0 governance. Release, corpus, repository and project migrations require their own competent authorities even after the semantic decision.

## 7. Version consequence

A name decision does not rewrite 3.0. If a successor name is selected, its first effective governed release must use a later version and preserve an explicit relation to the immutable SymK 3.0 baseline. The 3.1 stage must determine whether the change is appropriately expressed as 3.1 or requires a larger release boundary.

## 8. Non-effects

This amendment:

- does not classify “SymK” as obsolete;
- does not make “Symbiotic Knowledge” current or invalid;
- does not choose or solicit a replacement name;
- does not create DR-019 or DQ-027;
- does not complete a Human-review finding;
- does not modify DR-017;
- does not rename any file, identifier, repository, package, derived project or release;
- does not open 2.1.11, 3.0 or 3.1; and
- does not authorize a commit.

## 9. Gate

**PASS FOR CONTROLLED POST-3.0 DEFERRAL AND 3.1 SCAFFOLDING — NO NAME DECISION OR MIGRATION FOLLOWS.**
