# 1.4 Discovery Methodologies

_Phase 1 — Discovery_

## 1. Purpose / Objective

Define and maintain the **standard toolbox of discovery methods** available in PLC_1, and ensure that each product instance (IaaC, LexBrain, etc.) explicitly chooses and documents **which methods it actually used**.

In other words:

> 1.4 keeps the “how do we learn?” playbook coherent,  
> and forces each project to be honest about which parts of that playbook it applied.

---

## 2. Description

This node does **two things**:

1. At the **META level (SymK)**  
   - Defines the **method families** available in PLC_1 (interviews, competitor teardown, internal knowledge mining, risk framing, etc.).  
   - Lives in a generic toolbox document (the template file).

2. At the **project level (per product PLC)**  
   - Each project creates its own `1.4_Discovery_Methodologies` document that:  
     - Lists which META methods it actually used,  
     - Adds any project-specific twists,  
     - Identifies discovery gaps and next steps.

1.4 is *not* a place to dump raw notes.  
It is a **map of methods and coverage**, so later we can say:

- “We made this decision after doing X, Y, Z,”  
- or “We skipped A and B, so these blind spots still exist.”

---

## 3. Input

- **Required:**  
  - None strictly required to *define* the toolbox.

- **Optional (for updates/refinement):**
  - `type=doc, ref=PLC/1_Discovery/1.1_Product_Vision/product_vision.md`  
    (to align methods with the type of product we’re envisioning).
  - `type=doc, ref=PLC/1_Discovery/1.2_Market_Research/market_research_template.md`  
    (to cross-check whether the toolbox covers the needed market insights).
  - `type=external, ref=books/papers/on_discovery_and_research_methods`
  - `type=external, ref=prior_projects/discovery_playbooks`

---

## 4. Outcomes

For **SymK (META)**, 1.4 must produce:

- **[required]** `type=doc, ref=PLC/1_Discovery/1.4_Discovery_Methodologies/discovery_methodologies_template.md`  
  - Defines the **standard method families** and how to document them for any project.

- **[optional]** `type=data, ref=PLC/1_Discovery/1.4_Discovery_Methodologies/discovery_methodologies.json`  
  - Machine-readable catalogue of methods and tags (e.g. `{"family": "customer_exploration", "method": "problem_interview", "cost": "medium", "evidence_strength": "high"}`).

For **each project instance** (outside SymK), 1.4 must eventually result in:

- `type=doc, ref=<PROJECT>/PLC/1_Discovery/1.4_Discovery_Methodologies/<project>_1.4_Discovery_Methodologies.md`  
  - Instantiation of the META toolbox with:
    - Methods used,
    - Methods not used (explicitly stated),
    - Gaps and planned follow-ups.

---

## 5. Tools / Methodology

### Methods (for defining the toolbox itself)

- Scan existing **product discovery frameworks** (Lean UX, JTBD, etc.).
- Consolidate **internal project experience** into method families.
- Periodic **“toolbox review”** to add/remove methods and clarify descriptions.

### Tools

- Markdown editor for human-readable docs.
- Optional diagramming (Miro / Excalidraw) for visual method maps.
- Optional JSON editor for a machine-friendly `discovery_methodologies.json`.

### Templates

- `discovery_methodologies_template.md`  
  (the document that describes method families and how to report them).

If you already have `1.4_Discovery_Methodologies_Template.md` as a file, this spec is simply formalizing that as **the official output of 1.4** at the META level.

---

## 6. AI Support / Symbiotic Role

### Roles

- **method_cataloguer** – help list and classify methods into coherent families.  
- **gap_checker** – check if the chosen methods for a project **really cover** the questions in 1.1–1.3.  
- **normalizer** – ensure per-project 1.4 docs follow the same structure, so later analysis is possible.

### Prompt contracts (examples)

- `plc.1.4.list_methods`  
  - Input: existing docs + external references.  
  - Output: updated `discovery_methodologies_template.md`.

- `plc.1.4.project_adapt`  
  - Input: project’s 1.1, 1.2, 1.3 docs.  
  - Output: project-specific `1.4_Discovery_Methodologies` with:
    - Methods used,
    - Methods skipped,
    - Gaps and planned actions.

### Input context (AI)
